4  System structure

4.1 Available components

The HyEfRe Decision Support Tool allows you to configure your hydrogen infrastructure project by selecting different components through checkboxes in the System structure window. This section explains how to select components and which combinations are feasible.

4.1.1 Selecting components using checkboxes

When you open a scenario in the System structure view, you will see a panel with checkboxes that allow you to select which components to include in your analysis. The checkboxes are organized as follows:

  1. Navigate to System structure: In the sidebar, expand your scenario and click on System structure.

  2. Locate the checkbox panel: At the top of the main window, you will see “Step 1: Select your components” with the available components arranged in four labelled rows:

    • Purely electrical: RESu, LREP, PV, WF, Leonitus, BESS, El. cons.
    • H2 sources: Electrolyser, WT, LOHC import
    • H2 usage: H2 cons., H2 sales, Fuel cell, LOHC export
    • H2 byproducts: O2 sales, Waste heat

    The checkboxes in the H2 usage and H2 byproducts rows are shown only when the components they depend on are selected (see Component dependencies).

  3. Enable/disable components: Click on a checkbox to include or exclude that component from your scenario:

    • Checked (enabled): The component will be included in the optimization
    • Unchecked (disabled): The component will not be considered in the analysis

The following components can be selected via checkboxes:

Some components are present in the system but do not have checkboxes:

  • Electrical grid connection - connection to the grid is always present

  • Hydrogen storage - hydrogen compressor and tank (when a hydrogen source is active)
  • Waste source and storage - waste offered to the waste treatment plant and its storage (when WT is active)
  • Financial parameters - economic settings for the analysis
  • Simulation parameters - technical settings for optimization

4.1.2 Component dependencies

The DST enforces certain dependencies between components. Some components can only be selected if other components are already enabled. This ensures that the infrastructure configuration is technically coherent.

4.1.2.1 Hydrogen sources and hydrogen-dependent components

Hydrogen can be supplied on site by three components, the hydrogen sources:

  • Electrolyser, which produces hydrogen by water electrolysis
  • WT (waste treatment plant), whose reactors produce non-green hydrogen from waste
  • LOHC import, which releases hydrogen from bought LOHC in the dehydrogenation unit of LOHC purchase

The following checkboxes are shown while at least one hydrogen source is selected:

  • H2 cons. (Fixed Hydrogen Consumption)
  • H2 sales (Hydrogen Sales)
  • Fuel cell (Fuel Cell)

When the last selected hydrogen source is deselected, these components are deselected automatically and their checkboxes are hidden. If one source is deselected while another remains selected, they stay selected.

4.1.2.2 Waste heat

The Waste heat (Waste Heat Utilization) checkbox is shown only while the Electrolyser, the Fuel cell or WT is selected, because these are the components that produce waste heat. When the last of them is deselected, Waste heat is deselected automatically and its checkbox is hidden.

4.1.2.3 Components that need on-site hydrogen production

  • O2 sales (Oxygen Sales) is shown only while the Electrolyser is selected, because oxygen is a by-product of electrolysis.
  • LOHC export is shown only while the Electrolyser or WT is selected, because the hydrogenation unit of LOHC sales binds hydrogen produced on site. It is deselected when the last of them is deselected.

4.1.2.4 LOHC streams

The LOHC components (see Section 4.2.20) have no checkboxes of their own. They are shown according to the selected LOHC stream:

  • LOHC export: LOHC sales (including the hydrogenation unit) and LOHC tank. Requires the Electrolyser or WT.
  • LOHC import: LOHC purchase (including the dehydrogenation unit) and LOHC tank. The LOHC import checkbox is always visible.

The LOHC tank is shown for both streams. Only one LOHC stream can be active at a time: the two checkboxes behave like radio buttons, so checking one unchecks the other, and unchecking the active one leaves both unchecked.

4.1.2.5 Automatic selection

Some selections automatically select or deselect other components:

  • Selecting Electrolyser automatically selects H2 sales, O2 sales, Fuel cell and Waste heat. H2 cons. and LOHC export are not selected automatically.
  • Selecting LOHC import or WT automatically selects H2 sales if none of H2 cons., Fuel cell or H2 sales is selected yet.
  • Deselecting Electrolyser deselects O2 sales, and LOHC export if WT is not selected.
  • Deselecting the last hydrogen source (Electrolyser, WT or LOHC import) deselects H2 cons., H2 sales and Fuel cell.
  • Waste heat is deselected when none of the Electrolyser, Fuel cell and WT remains selected.
  • Selecting LOHC export automatically deselects LOHC import, and vice versa.

4.1.3 Feasible component combinations

Below are examples of common and feasible infrastructure configurations. The DST validates component combinations based on the following rules:

4.1.3.1 Validation rules

The system validates your component selection against the following rules. A click that would break one of them is ignored.

  1. Electrolyser and WT need a hydrogen use: If the Electrolyser or WT is selected, at least one of the following must also be selected:

    • Fuel cell (Fuel Cell)
    • H2 sales (Hydrogen Sales)
    • H2 cons. (Fixed Hydrogen Consumption)
    • LOHC export (LOHC export stream)

    Rationale: The electrolyser and the waste treatment reactors produce hydrogen, so there must be a way to utilize or sell the hydrogen.

  2. LOHC import needs a hydrogen use: If LOHC import is selected, at least one of the following must also be selected:

    • H2 cons. (Fixed Hydrogen Consumption)
    • Fuel cell (Fuel Cell)
    • H2 sales (Hydrogen Sales)

    Rationale: The hydrogen released from the bought LOHC must be used or sold.

  3. Hydrogen users need a hydrogen source: H2 cons., Fuel cell and H2 sales can only be selected together with the Electrolyser, WT or LOHC import. Waste heat can only be selected together with the Electrolyser, the Fuel cell or WT.

  4. LOHC export requires on-site hydrogen production: LOHC export can only be selected together with the Electrolyser or WT.

  5. One LOHC stream at a time: LOHC export and LOHC import cannot both be selected.

  6. At least one electric source: The configuration must include at least one of:

    • El. grid (Electrical Grid)
    • LREP (Local Renewable Energy Plant)
    • PV (Photovoltaic system)
    • WF (Wind Farm)
    • Leonitus (Leonitus wave energy converter)

    Rationale: The system needs at least one source of electricity.

  7. At least one electricity consumer: The configuration must include at least one of:

    • Electrolyser (hydrogen production)
    • El. cons. (Fixed Electricity Consumption)
    • BESS (Battery Storage)
    • LOHC import (the dehydrogenation unit of LOHC purchase uses an electric heater)
    • WT (waste treatment reactors)

    Rationale: There must be a consumer for the electricity supplied by the sources.

4.1.3.2 Invalid combinations

If you try to select an invalid combination of components, the application will:

  1. Reject the change: The component selection will not be updated
  2. Maintain valid state: The previous valid configuration will remain active

For example, the following combinations are invalid:

  • Electrolyser or WT without Fuel cell, H2 sales, H2 cons. or LOHC export: The produced hydrogen must be used somewhere
  • LOHC import without H2 cons., Fuel cell or H2 sales: The released hydrogen must be used somewhere
  • Fuel cell, H2 sales or H2 cons. without Electrolyser, WT and LOHC import: There is no hydrogen to supply them
  • Waste heat without Electrolyser, Fuel cell and WT: There is no component that produces waste heat
  • LOHC export without Electrolyser and WT: The hydrogenation unit needs hydrogen produced on site
  • LOHC export together with LOHC import: Only one LOHC stream can be active
  • No electric source: There must be at least one source of electricity (El. grid, LREP, PV, WF, or Leonitus)
  • No electricity consumer: There must be at least one consumer (Electrolyser, El. cons., BESS, LOHC import or WT)

4.1.3.3 Examples of feasible combinations

  • Electricity only: PV, BESS and El. cons. (no hydrogen components).
  • Hydrogen production and sale: Electrolyser with H2 sales (O2 sales, Fuel cell and Waste heat are optional).
  • Hydrogen export as LOHC: Electrolyser with LOHC export.
  • Hydrogen import as LOHC: LOHC import with H2 sales and/or Fuel cell, without the Electrolyser.
  • Electrolyser supplemented by LOHC import: Electrolyser and LOHC import with H2 sales and/or Fuel cell.
  • Hydrogen from waste: WT with H2 sales, H2 cons. (non-green allowed), Fuel cell and/or LOHC export to non-green customers.

4.2.2 Electrical grid connection

The Electrical grid connection component represents the interface between the renewable energy hub and the electrical grid. This component cannot be disabled.

It consists of 3 sections:

  • Grid connection: the physical characteristics of the grid connection (e.g. grid fees, peak power pricing).
  • Electricity supply: models and tariffs for purchasing electricity from the grid and feeding it into the grid.
  • Advanced features: optional grid-related constraints.

Before the 3 sections, there is a parameter influencing both Grid connection and Electricity supply:

Show predefined values for the country (dropdown menu)
The country is automatically selected according to the site location, but it can be changed manually. Available countries are those that participated in the NACHIP project: Croatia, Slovenia and Italy. Further available countries had participated in previous projects with the tool developers: Austria, Czechia, Germany, Hungary and Poland. If the selected location is in another country, the value of this parameter remains empty. With the selected country the tool offers grid connection and electricity supply types for that country, but any parameter can be entered manually.

Electricity supply parameters can be defined in two ways, each available in a separate tab:

  • Standard tariffs: defined through high, low, and optional weekend tariffs.
  • Custom price profile: defined by importing external time-series data of electricity prices.

4.2.2.3 Advanced features

This section provides additional constraints related to electricity import, export, and price behavior. Certain options are mutually exclusive and cannot be enabled simultaneously.

Parameter Description
Electricity export is not possible
[checkbox]		 Enable this option if electricity can be imported from the grid but cannot be exported to it. When enabled, the model does not allow feed-in of surplus electricity to the grid. All locally generated electricity must either be consumed on-site or curtailed. This option is applicable in cases where grid injection is not permitted by the DSO or contractual arrangements. If enabled, the following options are automatically disabled: Electricity import is not possible, Energy export limited to the imported amount
Electricity import is not possible
[checkbox]		 Enable this option if electricity can be exported to the grid but cannot be imported from it. When enabled, the system cannot purchase electricity from the electricity supplier. This is typically relevant when optimizing a generation plant with storage, where charging from the grid is not permitted by the DSO. The only exception is the renewable energy surplus (RESu, Section 4.2.3): if RESu is active, its surplus energy can still be taken from the grid, while purchasing from the supplier remains blocked. If enabled, the following options are automatically disabled: Electricity export is not possible, Energy export limited to the imported amount.
Energy export limited to the imported amount
[checkbox]		 Limits total exported electricity to the total imported electricity over the simulation period. This reflects regulatory or contractual conditions where feed-in remuneration is restricted to the amount of previously imported energy. Such schemes are designed to ensure that the prosumer remains primarily a consumer rather than a net producer. If enabled, the following options are automatically disabled: Electricity export is not possible, Electricity import is not possible.
Price of electricity cannot be negative
[checkbox]		 Prevents the effective electricity purchase price from becoming negative. When using custom electricity price profiles (e.g., day-ahead market data), negative prices may occur. In practice, however, retail consumers purchasing electricity through a supplier are typically not remunerated for consumption during negative price periods. If this option is enabled, any negative energy price is set to zero. It is recommended to keep this option enabled when electricity is purchased or sold through a supplier rather than directly on wholesale energy markets.

4.2.2.4 Optimization output

After running the optimization, the tool calculates the optimal technical and economic values for the defined scenario. This subsection shows what variables are tied to the Electrical grid connection component, while the results are presented in Results (Chapter 5).

Variable Description
Grid connection enlargement If the existing grid connection capacity is insufficient to satisfy the optimized power flows, the model determines the required:
- Grid connection capacity enlargement [kW]
- Investment cost of enlargement [€]
The investment cost is calculated according to the parameters defined in Section 4.2.2.1 – capacity price and/or distance-based cost components. If no enlargement is required, the investment cost is zero.
Electricity import from supplier The optimization determines the time-dependent profile of electricity purchased from the supplier. Results include:
- Electricity import profile as mean powers for each time step [kW]
- Operating cost of imported electricity [€]
The operating cost is calculated using: energy prices, additional fees, and taxes. If the total operating cost is negative, it indicates that revenue from electricity export exceeds the cost of electricity import during the simulation period. In that case, the hydrogen hub generates net income from electricity production.
Electricity flow through the grid connection The tool also provides the time-dependent profile of electricity flowing through the physical grid connection. This profile represents the actual power exchange at the connection point and may differ from the electricity purchased from the supplier. The difference occurs because the RESu component (Section 4.2.3, if enabled) acts as a secondary supplier. Therefore, grid fees are calculated based on the total electricity flowing through the connection. Outputs include:
- Electricity flow profile as mean powers for each time step [kW]
- Total cost of grid fees [€]
Monthly peak power For each month included in the simulation period, the model determines peak import power [kW] and peak export power [kW]. Peak values are used to calculate capacity-based charges according to the defined peak power price. The resulting output includes:
- Monthly peak values [kW]
- Total peak power cost over the simulation period [€]
If the simulation covers only part of a month, the peak power charge is still applied for that month, according to the defined pricing rules.
NoteTime resolution and profile length

All resulting time-series outputs (electricity import, export, and grid flow profiles) are generated according to the Simulation parameters – sampling time, start date, end date. The length of the output profiles therefore directly corresponds to the simulation settings.

Common issues and solutions

The RESu component (Section 4.2.3) can still be used together with it, so the system can take renewable surplus energy from the grid while buying no electricity from the supplier. This is the intended setup for e.g. a hydrogen plant that is allowed to run only on renewable surplus (HPM).

The RESu energy flows through the grid connection, so it is still counted in the peak power and connection size.

In time steps with available renewable surplus, electricity cannot be exported to the grid and the RESu energy cannot be sold back to the supplier. The RESu energy can only be consumed on site, or left unused.

4.2.7 Leonitus wave energy converter

The Leonitus wave energy converter (WEC) component represents the Leonitus wave power plant that produces electricity from waves. The plant is sized by its installed power \(S_{\mathrm{LWEC}}\) [kW], which the optimization determines. The plant is controllable, so in every time step it can produce any power between zero and its installed power:

\[ 0 \leq P_{\mathrm{LWEC}}(k) \leq S_{\mathrm{LWEC}} \leq S_{\mathrm{LWEC}}^{\max}. \]

Because the production can always be lowered, the plant never makes the problem infeasible when its electricity cannot be used.

The wave potential of the site is expressed by the unit price [€/kW]. One Leonitus plant (19 m x 16 m x 8 m) costs about 1.5 M€ and gives a constant 1 MW at the location Žigljen, i.e. 1500 €/kW. The same plant gives a lower constant power at a site with a weaker wave potential (e.g. 900 kW, i.e. 1667 €/kW) and a higher one at a site with a stronger potential (e.g. 1100 kW, i.e. 1364 €/kW).

The classic wave energy converter, sized by its length and a wave power profile, is no longer available. Projects saved with it are opened without it, and the Leonitus WEC is not selected in them.

4.2.10 Electrolyser

The electrolyser is the key component in hydrogen production. It uses electricity to split water molecules into hydrogen and oxygen, while producing heat due to inefficiencies in the conversion process. Therefore, it has 2 inputs (electricity and water) and 3 outputs:

  • Hydrogen (H\(_2\)) – the main output of the electrolyser.
  • Oxygen (O\(_2\)) – a byproduct of electrolysis that can be utilized or released into the atmosphere.
  • Heat – thermal energy resulting from conversion losses. The tool distinguishes between low-temperature (LT) and high-temperature (HT) heat. An electrolyser may produce either of these, both, or none, depending on the selected configuration.

The user can specify multiple electrolysers, each with its own set of parameters. An electrolyser is added by clicking on the Add new electrolyser button.

By right-clicking on an electrolyser node, a pop-up menu appears with the following options:

  • Rename electrolyser – change the name of the electrolyser.
  • Delete electrolyser – removes the electrolyser from the overall setup.

4.2.11 Water supply

Water is a feedstock for hydrogen production via electrolysis. The primary source is the water grid, while rainwater and a body of water can serve as additional renewable sources. All water used must be demineralized before entering the electrolyser. This section describes the parameters for the following components:

  • Water grid connection: the primary source of water. It is assumed that it has no limit on usage. It is used if any hydrogen is being produced.

  • Rain collection: a secondary water source limited by the local rainfall and the collection area. If enabled, it requires a water pump and a water tank. Monthly precipitation data is obtained from Open-Meteo API through internet.

  • Body of water: a secondary water source such as a river, lake, stream, or estuary. Daily availability is limited. If enabled, it requires a water pump.

  • Demineralizer: prepares water for the electrolyser by removing minerals and impurities. It is used for all water sources.

  • Water pump: pumps water from the water tank and from a body of water. Its electricity consumption comprises overcoming the height difference and any (ultra-)fine filtration. It is used if at least one of Rain collection and Body of water is enabled.

  • Water tank: stores collected rainwater. It is used only when Rain collection is enabled.

4.2.12 Hydrogen storage

The Hydrogen storage contains the hydrogen compressor (HCOMP1) and the hydrogen storage tank (HTANK). They are needed whenever there is a hydrogen source, i.e. the Electrolyser, the waste treatment plant (WT) or the LOHC import stream, so the header is shown when at least one of them is checked. It has no checkbox of its own.

Low-pressure hydrogen bus. Hydrogen producers (electrolysers, the waste treatment reactors of WT and the dehydrogenation unit of LOHC purchase) deliver hydrogen to a low-pressure hydrogen bus. Hydrogen from waste treatment is always non-green. The bus has no storage: in every time step, all hydrogen that is produced must be used by the consumers connected to it:

  • Hydrogen compressor – compresses hydrogen from the bus into the hydrogen storage tank,
  • Hydrogenation unit of LOHC sales – loads hydrogen into the LOHC,
  • Fuel cell stacks – if they take hydrogen from the hydrogen bus,
  • Fixed hydrogen consumption – if it uses low pressure hydrogen.

Green and non-green hydrogen are kept apart on the bus and in the tank. The pressure of the bus is the lowest outlet pressure of the electrolysers, of the waste treatment reactors that produce hydrogen and of the dehydrogenation unit, or 30 bar if there are none. It is shown as Hydrogen bus pressure in the hydrogen compressor parameters. With the predefined reactors and dehydrogenation unit (2 bar), the bus is at 2 bar while WT or LOHC import is selected, which raises the power consumption of the hydrogen compressor and limits the fixed hydrogen consumption at low pressure.

  • Hydrogen compressor: compresses hydrogen from the hydrogen bus to the hydrogen storage tank using electricity. Its size is determined by the hydrogen mass flow rate, while its power consumption is calculated from the inlet pressure (pressure of the hydrogen bus) and outlet pressure (rated pressure of the hydrogen tank).
  • Hydrogen storage tank: stores hydrogen between production and consumption or sale. It supplies H2 sales (including gas grid injection), and the fuel cells and the fixed hydrogen consumption when they take hydrogen from the tank. The tank must be sized to store at least one full day of hydrogen sales and of the fixed hydrogen consumption taken from the tank.

Projects saved with earlier versions had these parameters in the Electrolyser header; they are moved here automatically when the project is opened.

Calculation of the compressor power consumption

The inlet pressure of the compressor is the Hydrogen bus pressure \(p^{hbus}\) and its outlet pressure \(p^{htank}\) is the Rated pressure of the hydrogen storage tank. Both are gauge pressures, so the atmospheric pressure \(p_{atm} = 1.01325\) bar is added to each of them to get absolute pressures. Assuming adiabatic compression of a real gas, the power consumption \(e_{el}\) in [kWh/kg] is:

where \(\eta_{el}\) is the compressor Efficiency and the physical constants of hydrogen are:

  • \(\kappa = 1.41\) – ratio of specific heat at constant pressure to that at constant volume,
  • \(Z = 1.0059\) – compressibility factor, which accounts for the deviation of hydrogen from an ideal gas (taken as constant, which has negligible effect on accuracy),
  • \(R = 0.00114563\) kWh/(kg K) – individual gas constant,
  • \(T = 298\) K – temperature of hydrogen during compression.

\[e_{el}(a) = \frac{1}{\eta_{el}} \, \frac{\kappa}{\kappa - 1} \, Z \, R \, T \left[ \left( \frac{p^{hsale}(a) + p_{atm}}{p^{htank} + p_{atm}} \right)^{\frac{\kappa - 1}{\kappa}} - 1 \right]\]

If the required pressure is not higher than the tank pressure, the power consumption is 0. Assuming adiabatic compression of a real gas, the power consumption \(e_{el}\) in [kWh/kg] is:

\[e_{el} = \frac{1}{\eta_{el}} \, \frac{\kappa}{\kappa - 1} \, Z \, R \, T \left[ \left( \frac{p^{otank} + p_{atm}}{p^{elys} + p_{atm}} \right)^{\frac{\kappa - 1}{\kappa}} - 1 \right]\]

where \(\eta_{el}\) is the compressor Efficiency and the physical constants of oxygen are:

  • \(\kappa = 1.40\) – ratio of specific heat at constant pressure to that at constant volume,
  • \(Z = 0.99935\) – compressibility factor, which accounts for the deviation of oxygen from an ideal gas,
  • \(R = 7.21701 \cdot 10^{-5}\) kWh/(kg K) – individual gas constant,
  • \(T = 298\) K – temperature of oxygen during compression.

If the tank pressure is not higher than the inlet pressure, the power consumption is 0. The electrical power of the compressor in each time step is \(e_{el}\) multiplied by the mass flow of oxygen compressed into the tank.

4.2.16 Fuel cell stack

The fuel cell stack is a component that produces electricity and heat from hydrogen. Normally, fuel cell refers to a single electrochemical cell, while fuel cell stack refers to a series of individual fuel cells connected together with all other necessary elements to make a functional electricity generation unit used in real applications.

It is considered a combined heat and power (CHP) technology by the EU in Directive 2012/27/EU. It combines hydrogen and oxygen molecules into water to produce electricity while producing heat due to inefficiencies in the conversion process. The hydrogen is supplied from the hydrogen storage tank while the oxygen comes from air. Therefore, it has a single input (hydrogen) and 3 outputs:

  • Electricity – the main output of the fuel cell stack. It can be considered green or non-green depending on the type of hydrogen used.
  • Heat – thermal energy resulting from conversion losses. The tool distinguishes between low-temperature (LT) and high-temperature (HT) heat. A fuel cell stack may produce either of these, both, or none, depending on the selected configuration.
  • Water – in the form of steam. It can be extracted during electricity production, saved in the water tank and reused later.

The user can specify multiple fuel cell stacks in order to find the most suitable for the investment, each with its own set of parameters. Optimization will determine the optimal size of each stack as nominal electrical power. A fuel cell stack is added by clicking on Add new fuel cell stack button.

By right-clicking on a fuel cell stack node, a pop-up menu appears with the following options:

  • Rename fuel cell stack – change the name of the fuel cell stack.
  • Delete fuel cell stack – removes the fuel cell stack from the overall setup.

Hydrogen taken from (radio button above the stacks) selects where all fuel cell stacks take hydrogen from:

  • Hydrogen tank (default): hydrogen is taken from the hydrogen storage tank (see Section 4.2.12), so it can be produced at one time and used later.
  • Hydrogen bus: hydrogen is taken directly from the low-pressure hydrogen bus, without compression, so the fuel cells can only use hydrogen at the same time it is produced by the electrolysers or the dehydrogenation unit.

4.2.17 Waste heat

The heat generated from conversion losses of the electrolysers and/or the fuel cell stacks, i.e. from their cooling systems. This heat can be supplied to a local consumer within the renewable energy hub (e.g., a building, a greenhouse, a drying facility, etc.) and/or exported to a district heating (DH) network.

In the case of local heat consumption, any excess heat that cannot be absorbed by the consumer is considered wasted. If there is not enough heat produced by electrolysers and fuel cell stacks, additional heat must be purchased from the current heating source at its regular price. Therefore, the waste heat is effectively lowering current spending on heating requirements.

When heat is sold to a DH network, the model assumes no export limit by default. However, a limit can be imposed if the DH network cannot accept large amounts of heat.

The temperature level of both the local consumption and DH connection is assumed to be the same.

For more flexible heat delivery, the system includes a thermal energy storage (TES) unit.

If low-temperature heat must be upgraded to supply a high-temperature demand, a heat pump is required, which operates using electricity.

Heat from the electrolyser(s) and fuel cell stack(s) is delivered through low-temperature and high-temperature heat exchangers. These represent the complete heating subsystem, including pipes, valves, pumps, and control equipment.

Heat flows are automatically balanced by the optimization model between local consumption, TES, and DH export.

4.2.18 Waste treatment plant

The Waste treatment plant (WT) converts waste into hydrogen, electrical energy and heat. The plant consists of one or more reactors, each with its own process, technical and financial parameters. The tool determines the optimal size of every reactor, expressed as the amount of waste it can treat per day [t/day].

Besides hydrogen, the waste treatment process produces several by-products:

  • Electrical energy – the reactor can produce or consume electricity, depending on the process. Net production is fed to the electrical bus of the hub, while net consumption is supplied by the other electricity sources.
  • Heat – high- and low-temperature heat that can be used by the Waste heat component.
  • Carbon black – solid carbon that is sold to the market and generates revenue.
  • Tar – a by-product that must be disposed of, which causes an operating cost.
  • CO2 – emissions that are paid for at the CO2 emission price.

The waste for the reactors comes from the Waste source and storage component, which is enabled automatically together with the waste treatment plant.

Important

Hydrogen from the waste treatment plant is not green hydrogen. It is always counted as non-green hydrogen in the hydrogen balance and cannot be used to satisfy green hydrogen demand. In the same way, the electricity consumed by the reactors is supplied by non-green sources unless green electricity is available.

Operation of reactors

The waste treatment process is modelled with a daily time resolution. Reactors are assumed to operate continuously at their full installed capacity, i.e. every reactor treats an amount of waste equal to its size in every hour it is available. Availability is reduced only by planned maintenance and the following heating (start-up) period:

  1. At the maintenance start date, the reactor stops and treats no waste for the maintenance duration (in days).
  2. On the first day after the maintenance, at the start time of the reactor (hour of the day), the reactor starts preheating.
  3. During the starting duration (in hours), the reactor still treats no waste, but it consumes additional electricity – the starting electricity consumption surge. The surge is proportional to the reactor size and is modelled with the electrical time step, so it appears as a short peak in electricity consumption.
  4. After the preheating, the reactor returns to full operation.

The maintenance happens on the same date every year of the simulation. If a day is only partially affected by the maintenance (e.g. the day when the preheating ends), the reactor treats proportionally less waste in that day. If the maintenance duration is 0, there is no maintenance and no starting surge.

The outputs of a reactor are defined with the process matrix. Each output (electricity, heat, hydrogen, carbon black, tar, CO2) is calculated from the treated amount of waste and its composition (mass fractions of hydrogen, carbon and water defined in the Waste source and storage component), e.g. for electricity:

\[ P_\mathrm{el} = \dot{m}_\mathrm{waste} \cdot \left( \beta_\mathrm{H2,el}\,\omega_\mathrm{H2} + \beta_\mathrm{C,el}\,\omega_\mathrm{C} + \beta_\mathrm{H2O,el}\,\omega_\mathrm{H2O} \right) \]

where \(\beta\) are the process coefficients of the reactor and \(\omega\) are the mass fractions of the waste.

Use of produced hydrogen

Hydrogen from the reactors is compressed and stored in the hydrogen tank, from where it can be used by the Fuel cell stack or sold through H2 sales. If neither of these components is enabled, the hydrogen produced by waste treatment is released into the atmosphere.

4.2.19 Waste source and storage

The Waste source and storage (WSS) component defines how much waste is available to the Waste treatment plant, what its composition is, and how it can be stored before treatment. It does not have its own checkbox – it is enabled automatically together with the waste treatment plant.

Waste source

The waste source is defined by the amount of waste available over the year. The waste can be given as monthly amounts or imported as a profile with daily, weekly or monthly values. Since the waste treatment is modelled with a daily resolution, the tool splits the available waste into days of the simulation. Monthly and weekly amounts are considered to arrive evenly through the whole month or week.

The energy hub is paid a waste treatment remuneration for every tonne of waste it takes. By default, the optimization takes only the amount of waste that pays off. If Treat all waste is selected, all available waste must be taken and treated.

Waste storage

The waste storage decouples the arrival of waste from its treatment. Waste that is taken but not treated in a day is stored and can be treated in later days, e.g. during periods with less available waste or after the maintenance of the reactors. The optimization determines the optimal storage capacity. The amount of stored waste at the end of the simulation must be the same as at its beginning, so the operation can be repeated every year.

4.2.20 LOHC components

Liquid organic hydrogen carriers (LOHC) allow hydrogen to be stored and transported in liquid form. The LOHC components form two streams. The export stream (LOHC sales with its hydrogenation unit → LOHC tank) loads hydrogen produced on site into the carrier and sells the loaded LOHC; it requires the Electrolyser. The import stream (LOHC purchase with its dehydrogenation unit → LOHC tank) buys loaded LOHC and releases its hydrogen on site; it is always available. The released hydrogen can be used by H2 sales, the Fuel cell or the fixed hydrogen consumption, so LOHC import can be used without the Electrolyser. Only one stream can be active at a time. The stream is selected with the LOHC export / LOHC import checkboxes: checking one unchecks the other. The LOHC components are shown under three headers: LOHC sales (including the hydrogenation unit), LOHC purchase (including the dehydrogenation unit) and LOHC tank, which is used by both streams.

Hydrogen produced or released on site goes through the low-pressure hydrogen bus (see Section 4.2.12). The hydrogenation unit takes hydrogen from the bus, and the dehydrogenation unit delivers hydrogen to it.

4.2.20.1 LOHC sales

The LOHC sales component represents selling loaded LOHC to one or more customers. Each customer has a daily demand and a price, and may require green hydrogen. When loaded LOHC is delivered, the customer returns the same amount of unloaded LOHC. LOHC is sold only during the daily sales window, and the demand is satisfied only if it is economically viable. All quantities are expressed as mass of bound hydrogen.

The hydrogen is bound to the LOHC on site by the hydrogenation unit, which is defined in the Hydrogenation unit (advanced) section at the bottom of this component.

The component is part of the LOHC export stream and is shown only when the LOHC export checkbox is checked (see Section 4.2.20).

4.2.20.3 LOHC tank

The LOHC tank stores the liquid organic hydrogen carrier (LOHC). A single tank stores both unloaded and loaded LOHC, separated by a flexible membrane, so the amount of carrier in the tank is constant. The tank size is the mass of hydrogen it holds when all of its LOHC is loaded [kg]. The investment includes the tank and the first fill of the carrier.

The LOHC tank is also where the carrier is chosen. The carrier defines the hydrogen weight capacity, the carrier price and the reaction heat of the hydrogenation unit of LOHC sales.

4.2.20.3.5 Troubleshooting

Common issues and solutions:

  • Invalid hydrogen weight capacity: The hydrogen weight capacity must be greater than 0 wt% and less than 100 wt%.
  • Invalid carrier price: The carrier price must be greater than or equal to zero.
  • Invalid sizes: The existing, minimum and maximum sizes must be greater than or equal to zero, and the minimum size must not be greater than the maximum size.
  • Invalid financial parameters: All prices must be greater than or equal to zero, the lifetime must be at least 1 year, and the subsidy must be between 0 % and 100 %.
  • Reaction heat changed unexpectedly: Choosing a carrier overwrites the reaction heat of the hydrogenation unit. If you entered a custom reaction heat, enter it again after choosing the carrier.
  • Solid carriers: 2-methyl indole and N-ethylcarbazole are solid at ambient temperature. Heating of the storage is not modelled.

4.2.22.2 Understanding time sampling

The sampling time determines the time resolution of the optimization model. There is a trade-off between accuracy and computational complexity:

  • Hourly sampling (1 hour): Provides the highest accuracy for modeling daily fluctuations in electricity prices, renewable generation, and demand. This is the default and recommended setting for most analyses.

  • 2-4 hour sampling: Reduces computational time but may miss some short-term dynamics. Suitable for preliminary analyses or when investigating seasonal patterns.

  • Daily sampling (24 hours): Very fast but may not capture important intra-day effects. Typically used only for hydrogen part components which are modeled with daily resolution.

The electrical sampling time should always be less than or equal to the hydrogen/heat sampling time. The tool will automatically enforce this constraint.

4.2.22.3 Simulation period

The simulation period defines the time horizon for the optimization:

  • Full year (default): January 1 to December 31. All hourly profiles are used directly.

  • Partial year: Any period up to 365 days. If the period is shorter than a year, the profiles are repeated to fill the year. For example, if you simulate January to March, the model will repeat Q1 data for the remaining months.

The default simulation period is one full year (365 days).

4.2.22.4 Troubleshooting

  • Simulation duration too long: If the simulation period exceeds 365 days, an error message will be displayed. Reduce the simulation duration to a maximum of one (non-leap) year.

  • Optimization timeout: If the optimization does not complete within the specified timeout, consider:

    • Increasing the optimization timeout
    • Increasing the sampling time (e.g., from 1 hour to 2 hours)
    • Reducing the simulation period
    • Simplifying the system configuration by removing some components

  • Sampling time mismatch: If the electrical sampling time is greater than the hydrogen sampling time, the tool will automatically adjust the hydrogen sampling time to match.

4.3 Run optimization

After configuring all system components and their parameters, click Run optimization to generate the results. Once clicked, the tool performs the following sequence of operations:

  1. Project save prompt

: The tool first asks whether you want to save the project before starting the optimization. You can choose to: - save the project,
- continue without saving, or
- cancel the optimization.

Saving the project is recommended in case an error occurs and the application closes unexpectedly.
  1. Data validation

: The tool validates all parameters and their combinations to ensure they are within allowed ranges. If an invalid value is detected, a pop-up window titled Input validation failed appears. The message: - identifies the component where the issue occurs, and
- explains the reason for the failure.

Only the first detected issue is shown. After resolving it, run the optimization again to reveal any remaining issues.
  1. Data processing

: The tool prepares all required inputs for the optimization, including: - obtaining profiles from online sources (PVGIS, renewables.ninja, Open-Meteo),
- scaling profiles according to user-defined values,
- generating and converting additional parameters (e.g., unit adjustments).

During this phase, additional validation is performed on the processed data.  
If validation fails here, the cause is usually:
- an incompatible combination of parameters, or  
- a temporary internet connectivity issue.
  1. Problem generation

: After successful data preparation, the tool formulates the optimization problem and passes it to the solver.

  1. Solving the problem

: The optimization problem is solved using the open-source HiGHS solver. When the solver finishes, one of the following status messages is displayed: - Successful optimization – the optimal solution was found.
- Time limit reached – a feasible but suboptimal solution was obtained.
- Unexpected error – the solver failed to complete.

  1. Results post-processing

: After a successful run, the tool processes the results for presentation. A new window (Results) is created under the scenario tree node and automatically opened in the main workspace.

Waiting
During the entire procedure, a message Working, please wait… is displayed together with a loading indicator. While optimization is running:
  • the user interface is temporarily disabled,
  • no interaction is possible, and
  • the process cannot be stopped from within the application.

Stopping the optimization is planned for future releases. Currently, it can only be terminated via the system task manager.

Saving the data
Results are not saved automatically after optimization. Make sure to save the project manually to preserve the results.
